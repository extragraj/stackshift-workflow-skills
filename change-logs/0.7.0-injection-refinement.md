# 0.7.0 — Injection refinement (full content + injection map)

## TL;DR

Four changes:

1. **Workflow files no longer reference uninstalled protocols.** Each protocol's *Action* and *Done-when* checklist items now live in `protocols/_registry.json` and are injected into each workflow step's `CLI:PROTOCOLS` marker. The static "Required actions / Recommended actions / Required done-when / Recommended done-when" sections were removed from `workflow/*.md` — the agent only sees protocols that are actually installed.
2. **Cleaner protocol-list headers.** The parenthetical hints (`(block on violation)`, `(guidance only — do not block)`, `(apply if installed)`) were dropped from the injected protocol list. Tier is conveyed once per action / done-when row via a single italic tag.
3. **`workflow/checklist.md` is CLI-injected.** A new `CLI:CHECKLIST` marker replaces the hardcoded `Required / Recommended / Protocol-conditional` sections with an aggregated, tier-grouped list of `doneWhen` items sourced from every installed protocol. Universal step-by-step quality gates stay static.
4. **New `injection-map.json` and pruned `_step-map.json`.** Bootstrap now writes `.stackshift/injection-map.json` — a dynamic record of where each installed protocol got injected, ordered by step (1 → 5) then cross-cutting. The materialized `protocols/_step-map.json` is pruned to the installed subset.

Plus: the `tiers` description block was dropped from `seeds/_registry.json` (it was never read).

## Why

A few rough edges from 0.6.0 surfaced during the audit:

- **Workflow files still contained content for protocols that the user did not install.** `workflow/1-schema-fields.md` listed "Recommended actions" and "Recommended done-when" bullets for `field-reuse-first`, `hide-if-variant`, `preview-conventions`, `array-layout` even when none of those were installed. Same in Step 2 for `section-directory-layout`. The injected CLI:PROTOCOLS block listed the right protocols, but the static prose below didn't.
- **The tier parenthetical wording was load-bearing only for the model.** Humans skimming the workflow file got noise; the model already knows the tier from the heading.
- **There was no machine-readable record of where each installed protocol got injected.** The static `_step-map.json` was authoritative for the CLI but listed protocols the user didn't install, so it could not be quoted directly as the "what got injected" answer.

## What changed

### Protocol-driven action / done-when content

`protocols/_registry.json` gains two optional fields per protocol:

```json
{
  "id": "factory-function-pattern",
  "tier": "required",
  ...
  "action": {
    "title": "Use the factory function pattern for any new field",
    "body": "Return a plain object. No `defineField()` / `defineType()` wrappers. ..."
  },
  "doneWhen": [
    "New fields follow the factory function pattern",
    "Plain object syntax — no `defineField()` wrappers"
  ]
}
```

The CLI emits both into each step's `CLI:PROTOCOLS` marker. Only protocols installed in this project produce output. Required come first, then recommended, then optional.

The `ProtocolEntry` TypeScript type in `cli/src/registry.ts` was extended with `action?: ProtocolAction` and `doneWhen?: string[]`.

### `buildProtocolsBlock` rewritten

`cli/src/writer.ts` — the marker body now contains three sections:

1. **Protocol list** (`**Required protocols:**` / `**Recommended protocols:**` / `**Optional protocols:**`) — no parentheticals.
2. **`## Actions`** — one `### <title>` per installed protocol with an `*<tier> — <id>*` annotation. Skipped if no installed protocol declares an action.
3. **`## Done-when`** — flat checklist, each item tagged with its protocol id (and tier for non-required).

If no protocols are installed for a step, the marker collapses to `_No protocols active for this step in the current install._` as before.

### Workflow files stripped to non-protocol content

Each `workflow/N-*.md` now keeps only:

- The CLI:PROTOCOLS marker.
- Generic structural content (decision tables, directory structure, code examples, naming conventions, sub-step sequencing).
- A single `## Always validate` (or `## Done when`) checklist limited to universal items (validator command, structural postconditions).

The static `## Required actions`, `## Recommended actions`, `## Required done-when`, `## Recommended done-when` sections were deleted from every workflow file. Step 4's protocol-conditional postcondition notes (`When `accessibility` protocol is active`, etc.) were moved into the corresponding protocols' `action` / `doneWhen` fields.

`SKILL.md` lost its stale "Note on `auto-verify-hook`" paragraph that lingered next to the CLI:CROSSCUT marker — the protocol's own row now appears in the table when installed and is absent otherwise.

### Repair refreshes the scaffold

`cli/src/repair.ts` gains `refreshSkillScaffold()` which re-copies `SKILL.md` and every `workflow/*.md` from the shipped skill source on every repair, before pruning and marker injection. Without this, users upgrading from 0.6.0 → 0.6.0A would keep the stale `## Required actions` / `## Recommended actions` sections from their existing install. Protocol files in `protocols/` are intentionally NOT touched here — they continue to flow through `pruneSkillFolderProtocolsAllPlatforms`.

### `injection-map.json`

`writeInjectionMap()` in `cli/src/writer.ts` produces `.stackshift/injection-map.json` on every init and repair (project scope only):

```json
{
  "description": "...",
  "generatedAt": "2026-05-20T07:50:44.324Z",
  "protocols": {
    "factory-function-pattern": {
      "steps": ["1"],
      "locations": ["workflow/1-schema-fields.md"],
      "crossCutting": false
    },
    "auto-verify-hook": {
      "steps": ["4"],
      "locations": ["workflow/4-variants.md", "SKILL.md"],
      "crossCutting": true
    }
  }
}
```

Entries are ordered by step (1 → 5), then cross-cutting protocols, then any installed protocols the step-map does not place anywhere. Only installed protocols appear. Cross-cutting protocols list `SKILL.md` as a location and have `crossCutting: true`.

### Materialized `_step-map.json` is pruned

`pruneSkillFolderProtocols` now rewrites `protocols/_step-map.json` in the install destination alongside `_registry.json` — both `steps[]` and `crossCutting[]` arrays are filtered to the installed protocol set. Steps with no installed protocols become `[]` rather than being deleted.

### `seeds/_registry.json` `tiers` block removed

The `tiers` description object was unused — the CLI never read it. Per-seed `tier` fields are unchanged; the `SeedEntry` TypeScript type was not modified.

## Migration

Automatic. Running `npx @extragraj/stackshift-skills init` or `repair` after upgrade:

1. Refreshes the CLI-owned scaffold files (`SKILL.md`, `workflow/*.md`) from the shipped source.
2. Rewrites the CLI:PROTOCOLS / CLI:SEED / CLI:CROSSCUT marker regions with the new action/done-when content.
3. Prunes the materialized `_step-map.json` and `_registry.json` to the installed subset.
4. Writes `.stackshift/injection-map.json`.

No data migration is required. `.stackshift/installed.json` and `.stackshift/protocols/*` are untouched.

## Testing

Verified across the existing `temp/required`, `temp/recommended`, `temp/full`, `temp/custom` installs plus a clean `init --tier required`:

- Required tier — Step 1 lists only the two required protocols and their actions/done-when. Steps 2 / 4 likewise show only their required entries. No `## Recommended actions` / `## Recommended done-when` sections anywhere. SKILL.md cross-cut block is empty.
- Full tier — all installed protocols show in each step's list, actions, and done-when. Cross-cut block has the three optional rows.
- `injection-map.json` exists, lists only installed protocols, and routes cross-cutting entries to `SKILL.md`.
- `_step-map.json` in `.agents/skills/stackshift/protocols/` is trimmed to the installed protocol set.
- `seeds/_registry.json` in the install destination has the `tiers` block stripped.
