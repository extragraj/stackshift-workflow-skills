# 0.7.2 — PostToolUse hook contract, Windows path fixes, .forgeignore trim, protocol-gated references

## What changed

Four targeted fixes for issues found in a 0.7.1 audit. No new features, no breaking changes to the protocol catalog or workflow shape — but `init` / `repair` rewrites the two `PostToolUse` hook entries with the corrected command form, so existing installs should re-run one of them after upgrading.

## Why it was broken

### 1. PostToolUse hooks used a non-existent env var

Both `auto-verify-hook` (UI Forge) and `auto-validate-hook` (StackShift) installed `PostToolUse` commands that referenced `"$CLAUDE_FILE_PATH"`. That env var is not part of the documented Claude Code hook contract — hooks receive a JSON payload on **stdin** of the shape `{ "tool_input": { "file_path": "..." }, ... }`.

In practice this meant:
- `auto-validate-hook` ran `validate --file ""` on every Write/Edit, which fell through to a project-wide walk and could fail spuriously on pre-existing required-tier violations in unrelated files.
- `auto-verify-hook` ran `node verify.js ""`, which UI Forge's `verify.js` short-circuits silently on (the bug just made the hook a no-op rather than a misfire).

### 2. Windows `.gemini/antigravity` path drift

`cli/src/repair.ts` hard-coded the string `'.gemini/antigravity'` for the gemini global directory, while `cli/src/writer.ts` used `join('.gemini', 'antigravity')`. On Windows these resolve to different paths under `homedir()`, so `repair` scanned a different directory than `init` had written to.

### 3. `auto-verify-hook` listed in both Step 4 and `crossCutting`

The protocol's own doc says it applies to Step 4 (Component Variant). `_step-map.json` had it under both `steps.4` and `crossCutting`, which caused it to appear in the Step 4 protocols block (with its `action` / `doneWhen` injected) **and** in the `SKILL.md` `CLI:CROSSCUT` discovery table.

### 4. `--seed` accepted unknown ids silently

`validateFlags` in `cli/src/flags.ts` passed `--seed <anything>` straight into `installed.json`. `repair` later surfaced the unknown id as a warning, but `init` never rejected upfront.

### 5. Version drift across release artifacts

`skill.version` was bumped to `0.7.1` but `package.json`, `cli/package.json`, and `README.md` still read `0.7.0` until `prepack` ran `sync-version.mjs`. Anyone running `pnpm dev` or installing from source saw stale version strings.

## What changed

### Fixed

- **`cli/src/validate.ts`** — Added a `--hook` flag. When set, the CLI reads the Claude Code PostToolUse JSON payload from stdin, extracts `tool_input.file_path`, and validates that file. If stdin is empty or the path is missing, exits 0 silently — Claude Code surfaces nothing.
- **`cli/src/writer.ts` `tryInstallAutoValidateHook`** — Hook command changed from `validate --file "$CLAUDE_FILE_PATH"` to `validate --hook`.
- **`cli/src/writer.ts` `tryInstallPostToolUseHook`** — UI Forge verify hook command now wraps `verify.js` in a small `node -e` stdin reader that extracts `tool_input.file_path` from the PostToolUse payload and execs `verify.js` with it as argv. Idempotency check tightened to match on the absolute `verify.js` path so unrelated user hooks with a `verify.js` substring are no longer clobbered.
- **`cli/src/repair.ts`** — `PLATFORM_GLOBAL_DIR.gemini` switched to `join('.gemini', 'antigravity')` so init and repair scan the same directory on Windows.
- **`skills/stackshift/protocols/_step-map.json`** — Removed `auto-verify-hook` from `crossCutting`. It now lives only under `steps.4`, where its `action` / `doneWhen` are injected.
- **`cli/src/flags.ts` `validateFlags`** — `--seed` is validated against the seed registry; unknown ids exit 1 with a listing of valid values.
- **`cli/src/writer.ts` `FORGEIGNORE_CONTENT`** — Seeded `.forgeignore` now contains only the UI Forge integration entries (`design/.handoff-cache/`, `design/claude-design-bundle/`). The `studio/`, `.sanity/`, `.next/`, `dist/`, `build/`, `out/`, `coverage/` defaults are gone — those belong in the project's own `.gitignore`, not in `.forgeignore`. The merge logic for existing `.forgeignore` files was simplified accordingly: if the UI Forge integration block is absent, it is appended; otherwise the file is left alone. Existing user entries are always preserved.
- **Protocol-gated references.** Protocol registry entries gained an optional `references: string[]` field listing reference files in `skills/stackshift/references/` that are conceptually tied to that protocol. The CLI prunes those references from the install destination when the protocol is not installed; universal references (not listed under any protocol) remain shipped. `claude-design-roundtrip.md` is now gated on `claude-design-handoff`. The repair flow re-seeds the `references/` folder from the skill source before pruning, so toggling a protocol on (via re-init or a manual `installed.json` edit + `repair`) restores its references.
- **`skill.version`** → `0.7.2`. `pnpm sync-version` propagated to `package.json`, `cli/package.json`, and `README.md`.

### Documentation updated

- `skills/stackshift/protocols/auto-validate-hook.md` — Snippet + intro updated to show `validate --hook` and explain the stdin-JSON contract.
- `skills/stackshift/protocols/auto-verify-hook.md` — Snippet updated to the node stdin-reader wrapper; added a note about upgrading from pre-0.7.2.

### Unchanged

- Protocol catalog (`_registry.json`) — no entries added or removed.
- Workflow file structure — Steps 1–5 + checklist unchanged.
- Materialization behavior in `runBootstrapMaterialization` — same files written, same idempotency.
- Public CLI surface (`init`, `repair`, `validate`) — same commands, only the `validate --hook` flag is new.

## Migration

Run **`npx @extragraj/stackshift-skills repair`** in any project that already has a 0.6.0–0.7.1 install. Repair will:

- Re-inject the corrected hook commands into `.claude/settings.json` (idempotent — replaces the old `$CLAUDE_FILE_PATH` entry).
- Refresh the `CLI:PROTOCOLS` / `CLI:CROSSCUT` marker regions so `auto-verify-hook` no longer appears twice.
- Update workflow scaffolding (`SKILL.md`, `workflow/*.md`) from the new shipped skill source.

No manual edits required.

## Tests

- `init --no-interactive --seed bogus` rejected with an exit code 1 and a listing of valid seed ids.
