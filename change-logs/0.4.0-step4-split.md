# 0.4.0 — Split Step 4 reference content into on-demand files

## What changed

`workflow/4-variants.md` shrinks from 19 KB to ~7 KB by moving reference-heavy content into three new on-demand reference files. Step 4 now only loads the deep reference material when it is actually needed.

### Added

- **`references/ui-forge-invocation.md`** — `${UI_FORGE_SKILL_DIR}` resolution (preferred `detect.sh` flow + 7-path fallback), the `--validate-input` pre-flight, both invocation forms (slash-command and `node invoke.js`), the Claude Design handoff variant, ref-selection rules, and the StackShift-specific patterns `ui-forge` must honor. Loaded by Step 4 at 4d once preconditions pass.
- **`references/anti-slop-check.md`** — fidelity checklist (padding, background, decorative elements, icon container, button style) plus reporting format. Loaded by Step 4 at 4d **only when** any `--refs` argument is an HTML or TSX file.
- **`references/failure-modes.md`** — full failure-mode matrix with Checker/Detection/Response columns and the recovery rule. Loaded by Step 4 at 4d **only when** a precondition trips, `ui-forge` returns non-zero, or a postcondition fails.

### Simplified

- **`workflow/4-variants.md`** — now contains only the 4a–4d strict ordering, modification-vs-full-generation matrix, props-interface rules, preconditions, postconditions, and pointers to the three new references. A new on-demand table at the top of the file enumerates which reference to load and when.
- **`SKILL.md` Section 3** — adds three new rows to the lookup router so the new references are reachable from any step that needs them, not just Step 4.

## Bugs fixed

**Step 4 paid the full reference-content cost on every cold turn.** The pre-0.4.0 `4-variants.md` inlined `${UI_FORGE_SKILL_DIR}` resolution, the invocation forms, ref-selection rules, the anti-slop checklist, and the failure-modes table — roughly 13 KB of reference material that the agent re-read every time it opened Step 4, even when it never reached the invocation. Fix: split the content into three on-demand references and trim the workflow file to the strict procedural shell.

## Token cost impact

Measured against the same `stackshift-retailsignsystems2026-mkdc` install profile used in the 0.3.0 change-log:

| Surface | 0.3.0 | 0.4.0 | Delta |
|---|---|---|---|
| `workflow/4-variants.md` (loaded on every Step 4 turn) | ~4,750 tokens | ~1,750 tokens | −3,000 |
| `references/ui-forge-invocation.md` | — | ~1,500 tokens (loaded once at 4d) | +1,500 |
| `references/anti-slop-check.md` | — | ~250 tokens (conditional) | +0–250 |
| `references/failure-modes.md` | — | ~750 tokens (only on failure) | +0–750 |
| **Cold Step 4 happy-path total** | **~4,750** | **~3,250** | **−31%** |

A failed Step 4 turn that needs the failure-modes reference pays roughly the same as before, but every other Step 4 turn — including all happy-path variant builds — drops by ~3K tokens. Across a typical 8-turn section build, savings compound because Step 4 happy paths are the common case.

## Migration for existing installs

No marker schema change. On the next `init` or `repair`, the CLI overwrites the materialized skill folder, so the three new reference files land automatically. Project-level customisations under `.stackshift/protocols/` and `.stackshift/references/` are untouched.
