# 0.7.1 — Protocol priority fix

## What changed

Injected workflow markers now link to `.stackshift/protocols/<id>.md` (the user-editable project copy) instead of `protocols/<id>.md` (the skill's bundled copy). The hardcoded `paired-mode-contract.md` reference in `SKILL.md` Section 3's lookup table is updated to match.

## Why it was broken

0.6.0 introduced CLI-injected CLI:PROTOCOLS markers in `workflow/*.md` to pre-resolve the active protocol set. The injected links used skill-relative paths (`protocols/<id>.md`), which resolve to `.agents/skills/stackshift/protocols/<id>.md`. This silently bypassed the documented project-override priority: agents followed the injected link to the skill copy and never read the materialized `.stackshift/protocols/<id>.md` copy that users are meant to edit.

The Protocol Discovery section in `SKILL.md` Section 3 documented the correct `.stackshift/protocols/` → `protocols/` fallback chain, but the injected links meant that chain was never followed for installed protocols.

## What changed

### Fixed

- **`cli/src/writer.ts` `fileRef` function** — `protocols/${p.dir|p.file}` → `.stackshift/protocols/${p.dir|p.file}`. Affects all injected CLI:PROTOCOLS blocks in every `workflow/*.md` file across all platforms. Rebuilt and repaired installs will now route agents to the project copy.
- **`skills/stackshift/SKILL.md` Section 3 lookup table** — `protocols/paired-mode-contract.md` → `.stackshift/protocols/paired-mode-contract.md`, consistent with the new marker behavior.

### Unchanged

- Seed file references (`seeds/<file>`) remain skill-relative — seeds are not user-editable at project level.
- Cross-cutting protocol keywords table in `SKILL.md` `CLI:CROSSCUT` — this is a discovery table, not a load link; no path change needed.
- `.stackshift/protocols/` files are never overwritten by `init` or `repair` — this was already true and remains so.
- Custom protocols registered only in `.stackshift/protocols/_registry.json` are still discovered via the Protocol Discovery chain in `SKILL.md` Section 3 (unchanged).

## Documentation updated

- `README.md` — "Project Customization" section rewritten to explain the `.stackshift/protocols/` link mechanism. "Customizing Protocols" section updated with an explicit "Editing an Installed Protocol" subsection and a clear note on custom protocol discovery.
- `CLAUDE.md` — Bootstrap flow description updated to reflect that injected markers link to `.stackshift/protocols/`.

## Migration for existing installs

Run `npx @extragraj/stackshift-skills repair` — the marker injection rewrites all workflow files with the corrected paths. No manual edits required.

`skill.version` bumped to `0.7.1`.
