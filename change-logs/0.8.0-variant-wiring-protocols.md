# 0.8.0 — Variant wiring protocols (naming, reuse, dynamic registry) + validator extension

## What changed

Three new protocols formalize variant-level conventions that were previously informal practice or documented only in `site-template-default`. One existing protocol gains a static validator check; four existing protocols get content updates to reflect the documented behavior. Pure content + validator changes — no breaking changes to the CLI surface, the workflow shape, or the marker schema.

## What was missing

Three rules from the `site-template-default` custom-variant workflow were not encoded in StackShift:

1. **Variant key sequence.** `variant_a` … `variant_z` before `variant_aa` … `variant_zz`. Skipping straight to two-letter keys (`variant_ac` after `variant_h`) silently breaks the three-way key contract across `variantsList[].value`, the `Variants` map, and the variant filename.
2. **Variant reuse before scaffold.** Three-step decision tree: reuse as-is → wrap from `dist/` → scaffold new. Parallel to the existing `field-reuse-first` protocol.
3. **`components/data/dynamic.ts` registration.** The second variant-preview path (live React render in the Studio variant picker, gated by `NEXT_PUBLIC_RENDER_DYNAMIC_COMPONENTS=true`). Without it, custom variants render with base-package initial values, which produces misaligned previews. Not a seeding strategy — operates at picker render time, complementary to `initialValue-seeding` (which operates at document-create time).

The existing `variant-router` protocol's canonical pattern also drifted from the source-of-truth in two ways: it used static named imports for built-in variants (the rule is "every entry uses `dynamic()`"), and it did not cover the `list.tsx` named-export switch (`.then((m) => m.<Name>)`) or the `{ ssr: false }` drop when converting to a local wrapper.

## Added

- **`protocols/variant-naming-convention.md`** (required, Steps 2 + 4).
  - Single-letter key sequence rule with stop-and-check decision table.
  - Three-way alignment requirement: identical string in `variantsList[].value`, `Variants` map key, and `variant_<x>.tsx` filename.
  - Registry entry with `action` + `doneWhen`. Listed under `steps.2` and `steps.4` in `_step-map.json`.

- **`protocols/variant-reuse-first.md`** (recommended, Step 4 — runs before 4a).
  - Three-step decision tree: reuse as-is → wrap from `dist/` → scaffold new.
  - Inspection commands for base-package and local variant enumeration.
  - Two worked examples (reuse as-is for matching shape, wrap for layout-only differences).
  - Registry entry with `action` + `doneWhen`. Listed first under `steps.4` so the agent runs the reuse gate before invoking `variant-router`.

- **`protocols/dynamic-variants-registry.md`** (recommended, Step 2).
  - Decision-gate-first structure: no-op when `NEXT_PUBLIC_RENDER_DYNAMIC_COMPONENTS` is unset / `false`.
  - Part A (variantsMap) + Part B (initialValuesMap with custom `initialValue/` override).
  - Explicit cross-link to `section-directory-layout` as the static-branch alternative.
  - Registry entry with `action` + `doneWhen` + keywords for cross-cutting lookup. Listed under `steps.2`.

- **`cli/src/validate.ts` — `checkVariantNamingConvention`.**
  - Scans `components/sections/**/index.tsx` for two-letter `variant_xy` keys in the `Variants` map.
  - Flags when `variant_z` is absent (two-letter keys are only valid after `variant_z` is exhausted).
  - Tiered as `required`. Fires through `auto-validate-hook` automatically.
  - `PROTOCOL_TIERS` table extended with `variant-naming-convention`, `variant-reuse-first`, and `dynamic-variants-registry` so tier resolution works even when the marker is silent on tier.

## Modified

- **`protocols/variant-router.md`**
  - Canonical pattern rewritten: all `Variants` entries use `dynamic()`. Built-ins import from the package's `dist/` path (`@stackshift-ui/<pkg>/dist/<pkg>_<letter>`); customs from `./variant_<x>`. Static `BaseVariants` block removed.
  - New "Hard rules" item: every entry uses `dynamic()`; applies to first creation of `index.tsx`, not just later edits.
  - New "Dist-path examples" table covering common packages where the dist file suffix differs from the package id (`statistics` → `stats_a`, `text-component` → `text_a`, etc.).
  - New "`components/list.tsx` integration" section: `.then((m) => m.<Name>)` for named exports; drop `{ ssr: false }` when switching to a local wrapper.
  - Three anti-pattern blocks added (star imports, package-root named imports, persisting `ssr: false`).
  - Registry summary + `action` body + `doneWhen` extended to mention the dist-path rule.

- **`protocols/one-time-custom-schema-setup.md`**
  - New Step 1: register the section in `schemas/.../sections/index.ts`. This was previously documented only in `workflow/2-section-schema.md`; the one-time protocol now centralizes it.
  - New "Studio variant detection — three-way alignment" callout listing the three conditions that must hold for a variant to appear in Studio (`Components` map, `allSchemas`, `variantsList[].value` ↔ `Variants` map).
  - New "Live preview rendering — env-flag note" section pointing at `dynamic-variants-registry` (env on) or `section-directory-layout` (env off).
  - Step 4 verification list extended to include the new conditions.

- **`protocols/section-directory-layout.md`**
  - `images/` section reframed as the **static branch** of variant-preview, with a decision-point table at the top selecting static vs dynamic based on `NEXT_PUBLIC_RENDER_DYNAMIC_COMPONENTS`.
  - Image guidance tightened from "~800–1200px wide, 16:9 or 4:3" to **800×600 JPG** to match `site-template-default`'s convention.
  - Bidirectional cross-link to `dynamic-variants-registry`.
  - Registry summary + `action` + `doneWhen` updated: `images/` is no longer unconditional; the picker preview path is chosen based on the env flag.

- **`protocols/hide-if-variant.md`**
  - New "Inverse pattern" section: how to show a field on only one variant by hiding it on every other (no `showIfVariantIn()` exists). Includes a maintenance note about extending the exhaustive list when adding new variants.

- **`protocols/auto-validate-hook.md`**
  - Static-check table extended with the new `variant-naming-convention` row.
  - Registry summary updated to include `variant-naming-convention` in the enforced-protocols list.

- **`workflow/4-variants.md`**
  - The 4b code example updated to use the dist-path `dynamic()` pattern matching the new `variant-router` canonical pattern. The static `BaseVariants` example is gone.
  - New `list.tsx` integration paragraph immediately after the example, restating the `.then((m) => m.<Name>)` and `ssr: false` rules.

- **`_step-map.json`**
  - `steps.2`: gains `variant-naming-convention` and `dynamic-variants-registry`.
  - `steps.4`: gains `variant-reuse-first` (front of list — runs before scaffold) and `variant-naming-convention`.
  - `crossCutting`: unchanged.

- **`_registry.json`**
  - Three new entries (`variant-naming-convention` required, `variant-reuse-first` and `dynamic-variants-registry` recommended).
  - `variant-router`, `section-directory-layout`, `auto-validate-hook` summaries / actions / done-when updated.

## Unchanged

- CLI public surface (`init`, `repair`, `validate`) — same commands, same flags. `validate --hook` contract preserved.
- Workflow step ordering and file structure.
- Marker grammar (`<!-- CLI:PROTOCOLS:BEGIN step=N -->`, `<!-- CLI:SEED:BEGIN -->`, `<!-- CLI:CROSSCUT:BEGIN -->`, `<!-- CLI:CHECKLIST:BEGIN -->`).
- Seed registry — `initialvalue-seeding` remains the only strategy. The new `dynamic-variants-registry` is explicitly **not** a seed strategy (operates at a different runtime layer).
- `PostToolUse` hook contract — `validate --hook` reads stdin payload as in 0.7.2.
- `auto-verify-hook`, `accessibility`, `brand`, `claude-design-handoff`, `paired-mode-contract`, `modal-sheet` — no changes.

## UI Forge boundary (intentionally not implemented here)

The `site-template-default` source guidance also surfaces a large body of UI body rules that belong on the UI Forge side:

- `@stackshift-ui` primitives only (no raw HTML in variant bodies).
- `className` prop merge semantics and `tailwind-merge` behavior.
- Built-in props API (`variant`, `size`, `fontSize`, `weight`, `maxWidth`, `align`, `justify`, `gap`).
- CSS variable theming (`bg-primary`, `rounded-global`, `font-global`).
- `StackShiftUIProvider` overrides (`Image`, `Link`, custom `Button`).
- Anti-patterns: `!important`, `globals.css` overrides, raw `<div>` + inline styles.
- HTML-to-TSX scaffold flow (`yarn generate`, `scaffold-from-html.js`).

These remain UI Forge's responsibility. StackShift surfaces them only through the paired-mode handshake (`a11yRequired`, `designStandards.brand`, etc.). The new `variant-router` content stays strictly on the wiring side — `Variants` map shape, props extraction, `list.tsx` integration — and never reaches into the variant body's JSX.

## Migration

Existing 0.6.0 – 0.7.2 installs:

```bash
npx @extragraj/stackshift-skills repair
```

Repair will:

- Refresh the `CLI:PROTOCOLS` marker regions so the three new protocols appear in their assigned steps (when installed).
- Re-copy `protocols/variant-router.md`, `one-time-custom-schema-setup.md`, `section-directory-layout.md`, `hide-if-variant.md`, and `auto-validate-hook.md` from the new skill source if they are not already materialized.
- Existing `.stackshift/protocols/*.md` files are **never** overwritten — projects that have hand-edited any of these keep their version. To pull the new content into a hand-edited project, delete the file in `.stackshift/protocols/` and re-run `repair`.

For projects that want the new protocols active:

```bash
# Add to recommended set
npx @extragraj/stackshift-skills init --tier recommended

# Or pick individually via the interactive prompt
npx @extragraj/stackshift-skills init
```

No code changes required in target projects to honor the updated `variant-router` rules — the rules apply to new variants written after the upgrade. Existing `index.tsx` files using the static `BaseVariants` pattern continue to compile; the validator does not retroactively flag them under `variant-router` because that check covers props/signature shape, not import style.
