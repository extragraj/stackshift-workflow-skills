# 0.3.0 — CLI-owned bootstrap, single install path

## What changed

Bootstrap is now performed end-to-end by the CLI. The three tier-bundle skill folders, the AI-side `bootstrap/` flow, and the `--no-materialize` deferred install path are all removed. The agent's only install responsibility is checking for `.stackshift/installed.json`.

### Removed

- **Tier-bundle skill folders** — `skills/stackshift-protocols-required/`, `-recommended/`, `-full/` are deleted. The tier metadata they encoded (`mode` and per-protocol `tier`) lives entirely in `.stackshift/installed.json` and `protocols/_registry.json`. No skill manifest now lists a tier router; agents discover protocols solely from the marker file.
- **AI-side bootstrap docs** — `skills/stackshift-core/bootstrap/install.md` (28 KB) and `skills/stackshift-core/bootstrap/modes.md` (6 KB) are deleted. Their content moved to `CLI_BOOTSTRAP.md` at the repo root (humans only; not shipped).
- **`--no-materialize` flag** — removed from `cli/src/flags.ts`. Passing it errors out with a migration note. The CLI now always performs full materialization.
- **Marker flags** — `bootstrapRequired` and `materializationDone` are no longer written to `.stackshift/installed.json`. Both are stripped from any pre-0.3.0 marker the CLI encounters.
- **Repo-root bootstrap guides** — `BOOTSTRAP_QUICK_REFERENCE.md` and `BOOTSTRAP_COMPREHENSIVE_GUIDE.md` are deleted; `CLI_BOOTSTRAP.md` is the single human reference.

### Added

- **CLI-side UI Forge integration** in `cli/src/writer.ts`. The Phase-2 work previously documented in `bootstrap/install.md` Steps 6a–6h and 7b now runs during `init`:
  - 7-path UI Forge skill-root resolution (`UI_FORGE_SKILL_DIR` env, four project-scope paths, three home-scope paths, prefers `scripts/detect.sh` when available).
  - `scan.js` invocation when `design/design-arch.json` is missing, with stderr scan-fallback banner capture.
  - `designStandards` payload merge into `design/design-arch.json`.
  - `_paired` mirror block write.
  - Version compatibility check against `references/versions.md`.
  - Optional `export-design.js` invocation when `claude-design-handoff` is selected.
  - Optional Claude Code `PostToolUse` hook merge when `auto-verify-hook` is selected and `.claude/` exists.
- **Legacy purge on every install** — `removeLegacyBundleFolders` and `stripLegacyBundleEntries` in `writer.ts` clean up pre-0.3.0 artifacts on every run. `repair` runs the same purge as its first step.
- **`CLI_BOOTSTRAP.md`** — human reference for the install flow. Documents marker schema, project artifacts the CLI writes, install modes, and reconciliation behavior.

### Simplified

- **`SKILL.md` Section 0** collapses from 60 lines to 12. The new check is "is the marker present? if yes proceed; if no tell the user to run init."
- **`prompts.ts`** — `runPrompts` now takes the existing tier directly (`'required' | 'recommended' | 'full' | 'custom'`) instead of a bundle-name string, since there are no bundle folders to detect.
- **`install.ts`** — the deferred-bootstrap branch and bundle-detection scan are removed. `install()` is now a linear flow: prompts → writeSelection → runBootstrapMaterialization → summary.
- **`registry.ts`** — `inferType` and `inferTier` drop their `stackshift-protocols-*` special cases.
- **`repair.ts`** — the multi-tier-bundle repair branch is replaced with the legacy-purge step. Seed reconciliation and materialized protocol reconciliation are unchanged.

## Bugs fixed

**Phase 2 silently skipped on every cold run.** The pre-0.3.0 marker schema wrote `materializationDone: true` on every CLI run and never cleared it. The agent's `SKILL.md` Section 0.2 told the agent to re-enter `bootstrap/install.md` for "Phase 2 only" on every cold load — but `bootstrap/install.md` Step 1 immediately routed back to "skip to Step 6". Many agents short-circuited and treated the flag as "bootstrap done", which dropped UI Forge integration silently. Fix: collapse the two-phase design. The CLI does everything; the marker carries no transient flag; the agent never re-enters bootstrap.

**Tier-bundle skill folders inflated cold-load tokens.** Each tier bundle was a 1.2–1.6 KB `SKILL.md` index pointing back to `stackshift-core/protocols/`. Agents enumerated them as separate skills in their manifest, paying ~3K tokens per cold run for routing information that already lived in `.stackshift/installed.json`. Fix: delete the folders.

**`bootstrap/install.md` reloaded on every cold turn.** A 28 KB document the agent re-read every time the marker had `materializationDone: true` or `bootstrapRequired: true`. Fix: delete the document; agents never load it.

## Migration for existing installs

The CLI handles this automatically. Running `npx @extragraj/stackshift-skills init` (or `repair`) on a pre-0.3.0 install:

- Removes `stackshift-protocols-{required,recommended,full,custom}/` from every platform skill root.
- Removes `stackshift-protocols-*` entries from every `skills-lock.json`.
- Strips `bootstrapRequired` and `materializationDone` from `.stackshift/installed.json`.

No manual intervention required. Users who scripted around `--no-materialize` will see a one-line error pointing them at this changelog.

|---|---|---|---|

| `bootstrap/modes.md` reference | 1,500 tokens | 0 | −1,500 |
| `SKILL.md` Section 0 | ~1,500 tokens | ~150 tokens | −1,350 |
| **Cold Step 4 turn total** | **~47,500 tokens** | **~34,500 tokens** | **−27%** |

A typical 8-turn section build on Open Router drops from ~400K input tokens to ~280K of skill-instruction surface.
