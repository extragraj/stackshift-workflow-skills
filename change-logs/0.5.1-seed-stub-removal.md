# 0.5.1 — Seed stub folder removal

## What changed

The `skills/stackshift-seed-initialvalue/` stub folder is deleted. Seed strategies no longer ship as separate skill folders; the active strategy id lives solely in `.stackshift/installed.json` `seed`, and the canonical content stays at `skills/stackshift-core/seeds/<strategy>.md`.

This mirrors the 0.3.0 removal of the tier-bundle folders (`stackshift-protocols-{required,recommended,full}`). The seed stub had the same pattern: a `SKILL.md` index pointing back to canonical content in `stackshift-core/`, with the agent never consuming it.

### Removed

- **`skills/stackshift-seed-initialvalue/`** — discoverable stub. Never copied to user installs by the CLI (`writer.ts` only ever shipped `stackshift-core`), so removing it has no runtime effect for users who installed via `npx @extragraj/stackshift-skills init`.
- **`stackshift-seed-` special cases in `cli/src/registry.ts`** — `inferType` and `inferTier` no longer infer from folder name prefix. `SkillType` collapses to `'core'`.
- **`scanForSeedFolders` / `removeSeedFromAllLocations` / `findSeedEntryByFolder` / `deriveSeedId` / `updateInstalledSeed` in `cli/src/repair.ts`** — the multi-seed reconciliation flow they fed is gone. Seed identity is unambiguous now (one field in one file).

### Added

- **Legacy purge for `stackshift-seed-*` folders** in `cli/src/writer.ts` (`removeLegacyBundleFolders`) and `cli/src/repair.ts` (`purgeLegacyBundles`). Any user install that has a stub folder from a prior version (or from `npx skills add`) gets it removed on the next `init` or `repair`. Matching `skills-lock.json` entries are stripped the same way pre-0.3.0 `stackshift-protocols-*` entries are.

### Simplified

- **`cli/src/repair.ts`** — seed handling collapses from ~80 lines of folder reconciliation to a single registry-membership check against `installed.json` `seed`.
- **`cli/src/install.ts`** — the misleading lock-file comment that claimed the CLI installs "one `stackshift-seed-*` folder" is corrected. The CLI ships only `stackshift-core`.

## Bug fixed

**Misleading documentation about what the CLI ships.** `cli/src/install.ts:12`, `README.md:135`, and `CLI_BOOTSTRAP.md:20` all stated that a `stackshift-seed-*` folder is copied to the target install when a seed strategy is selected. `writer.ts:989` actually only copies the skill flagged `type === 'core'`. The stub never reached user installs through the CLI; the discoverability was for `npx skills add`-style external scanners. Documentation now matches behavior.

## Migration for existing installs

Automatic. The next `npx @extragraj/stackshift-skills init` or `repair` removes any `stackshift-seed-*` folder and lock entry left over from prior versions. `.stackshift/installed.json` `seed` is untouched — that's the source of truth.

No CLI flags changed. No agent-facing behavior changed.
